# Release notes

- SCAP 1.4: `RES-181-1` (an `oval_system_characteristics` containing `system_data` but no `collected_objects`) is now reported as a warning (previously a validation error).
- SCAP 1.3 and 1.4: an `<xccdf:status>` value that is a valid XCCDF status value but not `draft`/`accepted` (`incomplete`, `interim`, `deprecated`) is now reported as a warning (`SRC-5-3`) noting the deviation from SP 800-126 Section 3.2.2. Previously this failed validation (1.3) or passed silently (1.4). Genuinely invalid status values remain an error (`SRC-5-1`).
- OVAL 5.11.2 system characteristics schematron: three asserts had inverted comparisons and errored on every collected value (`unix-sc:file_item` `user_id` and `group_id`, `win-sc:textfilecontent_item` `instance`). Any Linux result data stream with collected file items failed `SRC-330-3`. The tests now match the OVAL definitions schematron semantics: `user_id`/`group_id` >= 0, `instance` >= 1.
- SCAP 1.3 and 1.4: the `RES-136-2` `xccdf:target-address` check accepted only fully expanded 8-group IPv6 addresses, so every compressed (`::`) address failed, and the unanchored match let an address embedded in other text pass. The check now accepts compressed IPv6 (including IPv4-mapped forms) and an optional CIDR prefix length that some assessment tools append to interface addresses (`::1/128`, `fe80::1/64`), and anchors the match.
- SCAP 1.3 and 1.4: the `RES-136-2` `xccdf:target-address` check now accepts an IPv6 zone ID (RFC 4007) appended to the address (`fe80::1%lo0`). Some assessment tools report link-local interface addresses with a zone ID, and every such result file failed validation.
